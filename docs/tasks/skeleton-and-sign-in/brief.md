# Task brief：skeleton-and-sign-in（骨架與登入）

狀態：owner 於 2026-11-21 核准並說「開始」。owner 同意 `AUD-F01` 拆成兩段（假設 1）、
六個訊息採用 v2 的字串（假設 2），並決定謹慎程度為「謹慎」、預算 16 個 session。
owner 於 2026-11-22 另外同意：S-12 的容器映像由 CI 證明（issue #7）、時間以實際工作
時間計算、改寫 S-14 的第一項、時間預算延長 30 分鐘（共 4 小時 30 分）。

後續 task 地圖的第 2 個 task（見 `docs/tasks/system-design/task-map.md`）。依據的設計是
`docs/tasks/system-design/design.md`。

## 目標

任務完成後：

1. 員工、管理員與 owner 可以用瀏覽器登入與登出；密碼錯太多次會被鎖定，太久沒用會
   被登出，沒登入的人進不了任何受保護的頁面。
2. 系統有了之後每個 task 都要用的地基：統一的拒絕方式、權限檢查、稽核寫入、可控制
   的時鐘、設定檢查；之後的 task 只使用它們，不再各做一套。
3. 規格的例子會被自動執行：已建置的規則每次都跑，還沒建置的規則被清楚標示為
   「尚未建置」而不是失敗。
4. 成品是可以部署的形狀：可以建成容器映像、啟動前自動更新資料庫結構、缺少必要
   設定就拒絕啟動、有一頁顯示系統狀態。本 task 不實際部署。
5. 上一個 task 驗證時留下、指定由本 task 處理的問題都已處理。

## 不做什麼

- 不建置日報、審核、帳戶管理、薪資、材料、流水帳、檔案庫、稽核查閱。登入後看到的
  日報頁與確認頁只是寫著「尚未建置」的空殼，之後的 task 才填內容。
- 不做帳戶的新增、封存、改密碼、重設密碼（Task 4）。本 task 的帳戶只能由指令建立。
- 不做權限總表的逐格檢查。規格 `AUD-F01` 的「權限總表」（AUD-R02）與「每次被拒絕都
  留下紀錄」（AUD-R03）列出的動作分屬日報、薪資、材料等領域，那些動作在本 task 還
  不存在；這兩條規則留在「尚未建置」，由 Task 8 開啟（見假設 1）。
- 不實際部署，不連線任何真實的 Railway、Supabase 或物件儲存，不使用真實資料或金鑰。
- 不做檔案儲存、排程、銀行帳號加密、匯出。設定檢查只認得它們的設定名稱，並在
  狀態頁顯示「未設定」。
- 不新增 `.github/` 下的工作流程檔；CI 的內容會準備好交給 owner 加入（見假設 6）。

## 情境

規格領域：S-1 至 S-8 屬於「身分與帳戶」，S-9 屬於「稽核」；它們把規格裡已列在
「尚未建置」的規則建出來，行為不變，只有假設 2 新增的訊息字串例外。S-10 至 S-14 是
規格以外的交付。

**S-1 登入頁依群組列出名單**（IAM-R01，2 個 scenario）
- Given 有管理員、西區員工、南區員工與一位已封存的員工
- When 訪客在登入頁選「管理員」「西區」或「南區」
- Then 名單只列出該群組未封存的人；owner 列在管理員群組

**S-2 密碼正確就登入，並到自己角色的頁面**（IAM-R02，1 個 scenario）
- Given 一位員工、一位管理員與 owner
- When 他們各自以正確密碼登入
- Then 員工到日報頁，管理員與 owner 到確認頁

**S-3 登入失敗不透露帳戶的任何資訊**（IAM-R03，1 個 scenario）
- Given 一個存在的帳戶、一個不存在的名字、一個已封存的帳戶
- When 分別以錯誤密碼、任意密碼、正確密碼登入
- Then 三者都看到同一句「密碼錯誤，請重試」，沒有人被登入

**S-4 連續輸錯密碼會鎖定 15 分鐘**（IAM-R04 至 R06，5 個 scenario）
- Given 某人在 15 分鐘內已輸錯 4 次
- When 他再輸錯一次
- Then 帳戶被鎖定並看到「密碼錯誤次數過多，請在 15 分鐘後再試」，留下一筆由系統
  記錄的鎖定紀錄；鎖定期間連正確密碼也不行；滿 15 分鐘整就能登入；成功登入、鎖定
  結束、或安靜 15 分鐘後次數歸零；別人的帳戶不受影響

**S-5 同一個來源一分鐘最多嘗試登入 10 次**（IAM-R07，2 個 scenario）
- Given 同一個來源在 60 秒內已嘗試 10 次
- When 它再試一次，即使密碼正確
- Then 被拒絕；系統跑多個行程或重啟後，這個上限仍然成立

**S-6 30 分鐘沒有使用就要重新登入**（IAM-R10，4 個 scenario）
- Given 某人已登入
- When 他閒置 29 分 59 秒後操作，或閒置滿 30 分鐘後操作
- Then 前者照常，後者被要求重新登入；有操作就重新起算；逾時不影響已存的資料；
  沒有「記住我」

**S-7 登出立即生效**（IAM-R11，2 個 scenario）
- Given 某人已登入
- When 他登出
- Then 原本的登入狀態立刻失效；已登入的人打開登入頁會被帶到自己的頁面

**S-8 登入憑證受到保護**（IAM-R12，2 個 scenario）
- Given 某人已登入
- When 有一個會改變資料的請求帶著他的登入狀態、卻沒有防偽造憑證
- Then 被拒絕，留下一筆記錄他的名字的拒絕紀錄，其他什麼都沒變；登入用的 cookie
  不能被網頁程式讀取，正式環境只走加密連線

**S-9 沒登入的人進不了受保護的頁面，也不留紀錄**（AUD-R01，1 個 scenario）
- Given 一位沒有登入的訪客
- When 他直接開啟任何受保護的頁面或動作
- Then 被擋下，不寫任何紀錄

**S-10 規格的例子自動執行，未建置的規則不會被當成失敗**
- Given 規格有 137 條規則，其中 11 條在本 task 建置
- When 執行測試指令
- Then 這 11 條規則的 20 個 scenario 全部執行並通過；其餘規則的 scenario 顯示為
  「尚未建置」；把任何一條已建置的規則弄壞，測試就失敗

**S-11 在本機用一組指令啟動，並用瀏覽器登入**
- Given 一台有 Python 與 PostgreSQL 的電腦，沒有任何帳號或金鑰
- When 照說明執行啟動指令並載入示範帳戶
- Then 可以在瀏覽器打開登入頁，用示範帳戶登入、看到自己角色的空殼頁面、登出

**S-12 成品可以被部署**
- Given 本 repo 的程式
- When 建置容器映像並以正式環境的設定啟動
- Then 啟動前先更新資料庫結構；缺少必要設定時拒絕啟動並說明缺哪一項；狀態頁顯示
  資料庫可連線，檔案儲存與加密金鑰為「未設定」；同一個映像只改設定就能在本機
  執行

**S-13 第一位 owner 由一次性的指令建立**
- Given 一個剛建好、還沒有任何帳戶的系統
- When 執行建立 owner 的指令並當場輸入密碼
- Then owner 可以登入；再執行一次會被拒絕，因為 owner 只能有一位；密碼不出現在
  設定檔、程式或紀錄裡

**S-14 上一個 task 留下的問題已處理**
- Given `system-design` 驗證留下、指定給本 task 的四項（規格總數只檢查一處、差異
  清單漏列措辭差異、設計說本機與正式「只有三處」不同、OQ-9 沒有確定的字串）
- When owner 查看對應的文件與工具
- Then 規格的總數只寫在規格的首頁；那裡的每個數字、每一張列出 feature 的表、以及已開啟
  的規則數，改錯都會失敗；其他現行文件不寫總數，檢查工具會擋下常見的寫法，但不保證
  擋下每一種句子（owner 於 2026-11-22 同意改寫，原文是「規格的總數不論寫在哪裡，改錯
  任何一處檢查都會失敗」，兩次最終驗證顯示它做不到）；差異清單補上那四處措辭
  差異；設計的設定一覽與「本機與正式的差別」一致；六個訊息各自採用的字串已寫進
  規格的欄位表

## 怎麼試

1. 依 README 的步驟安裝並啟動本機的資料庫與應用程式，載入示範帳戶。
2. 打開登入頁：切換三個群組看名單；用員工、管理員登入各看一次落地頁；登出。
3. 用同一個帳戶連續輸錯密碼 5 次，看到鎖定訊息；用另一個帳戶仍可登入。
4. 登入後不操作，用說明裡的方式把時間往後調 30 分鐘，再點任何頁面，被要求重新
   登入。
5. 沒登入時直接輸入日報頁的網址，被帶回登入頁。
6. 執行測試指令，看到 20 個 scenario 通過、其餘標為尚未建置。
7. 建置容器映像；故意拿掉資料庫設定啟動，看到拒絕啟動的訊息。

4 小時、16 個 session（owner 核准時決定；一個 subagent 算一個 session）。

謹慎（owner 核准時決定）。之後每個 task 都建在這個地基上，這裡的
錯誤最貴，所以每張 ticket 合併前先獨立驗證，最後再驗證整個分支。

## 假設

owner 沒有明說、我先選定的預設；核准 brief 即表示同意，或請直接改。

1. **`AUD-F01` 拆成兩段。** task 地圖原本把整個 `AUD-F01` 放在本 task；但它的 AUD-R02
   與 AUD-R03 需要其他領域的動作才驗得了。本 task 建置檢查權限與記錄拒絕的機制
   （用 S-8 的防偽造情境與單元測試證明），AUD-R01 開啟；AUD-R02、AUD-R03 移到
   Task 8。task 地圖會跟著更新。
2. **六個規格沒有的訊息採用 v2 的字串**（未決問題 OQ-9），寫進規格的欄位表：
   沒選群組「請選擇類型」；超過登入頻率「登入嘗試過於頻繁，請稍後再試」；防偽造
   憑證不符「請求未通過驗證」；一般的權限不足「禁止存取」；登入逾時「請重新登入」；
   登出後「您已登出」。
3. **找不到的東西回「找不到」**（HTTP 404），不寫紀錄，不屬於規格的任何結果類別
   （OQ-3）。
4. **來源位址只信任部署平台的代理加上的那一段**；信任幾層是設定值，本機 0、平台 1
   （OQ-17）。
5. **示範帳戶**只在非正式環境可以載入：規格共用背景的 9 個帳戶，密碼是固定的示範
   密碼；正式環境執行這個指令會被拒絕。
6. **CI 由 owner 加入。** 我準備好工作流程檔的內容與說明，開一個 `needs-owner` 的
   issue；owner 加入之前，測試只在本機與驗證時執行。
7. **密碼規則**（長度、複雜度）屬於 Task 4 的「密碼變更與重設」；本 task 的建立指令
   只要求非空。
8. **登入失敗的計數與頻率限制都存在資料庫**，所以多個行程與重啟後都成立；已鎖定
   期間的嘗試不計入失敗次數，也不延長鎖定（沿用 v3 的做法）。
9. **閒置時間只由真正的操作延長**；瀏覽器背景自動發出的請求不算。本 task 沒有這類
   請求，之後的 task 若加入要遵守這一條。
10. **一個人可以同時在多個裝置登入**，各自獨立計算閒置時間；規格沒有限制。
11. **畫面**用繁體中文，版面從簡：登入頁、兩個空殼頁、頂端顯示名稱與角色及登出。
    側欄、收合等導覽細節屬於 Task 8 的檢查清單。
12. **瀏覽器冒煙測試**用 Playwright 涵蓋 S-11 的流程，納入測試指令；它需要的瀏覽器
    在這個環境已預先安裝。
