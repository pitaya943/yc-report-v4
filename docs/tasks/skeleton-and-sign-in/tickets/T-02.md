## Behaviours to prove

Spec scenarios (run from `docs/spec`, not copied)
1. Every scenario of rules IAM-R01, IAM-R02, IAM-R03 and AUD-R01 runs and
   passes: 5 scenarios, 11 cases.

Runner
2. A scenario whose rule is not in `implemented_rules.txt` is reported as
   skipped with the reason naming its rule; one whose rule is listed runs.
3. Adding a rule ID to the list without building it makes the suite fail (its
   scenarios run and have no steps).
4. The number of collected spec cases equals the `cases=` total printed by
   `tools/check_spec.py`; show the test failing when two scenarios in one
   feature share a name (in a throwaway copy).
5. A rule ID in the list that does not exist in the spec, or a duplicate line,
   fails a test.
6. Every `Refusal` message in `app/` appears word for word in
   `docs/spec/reference/appendix-b-fields.md`; show the test failing for a
   message that does not.

Sign-in details the scenarios do not pin down
7. An unrecognised group is INVALID with 「請選擇類型」; a missing name, or a
   name not in the chosen group's list, is INVALID with 「請選擇帳戶」.
8. The database never holds the password or the session token in plain form.
9. The response for an unknown name takes the password-verification path (a
   dummy verification is performed), so its timing is not distinguishable by
   skipping the hash.
10. A USER opening `/review`, or an administrator opening `/reports`, is
    FORBIDDEN with one `ACCESS_DENIED` row.

Carried over from the T-01 verdict (pull request 8, findings 1, 2, 3 and 5)
11. The time scan also catches `datetime.today()`, `time.monotonic()`, an
    aliased import (`from datetime import datetime as dt` then `dt.now()`,
    `from datetime import date as d` then `d.today()`), and SQL `timeofday()`
    and `'now'::timestamptz`; and it labels `time.localtime()` as a Python time
    read, not as an SQL one.
12. A test fails when the error handler stops rolling back the request's
    transaction before it writes `ACCESS_DENIED` (today removing that rollback
    leaves the suite green).
13. A `CLOCK_OFFSET_MINUTES` too large to apply is reported by `check-config`
    as a settings problem naming the setting, not as a traceback.
14. `serve` reports a migration failure as a migration failure, and any other
    database error at start-up under its own wording.
