## Behaviours to prove (each by a test seen to fail, or a recorded driven check)

Settings
1. With `DATABASE_URL` missing, `check-config` and `serve` stop with a non-zero
   status and a message naming `DATABASE_URL`; with several problems, all are
   listed at once.
2. `APP_ENV=production` with `PASSWORD_HASH_PROFILE=fast`, or with a non-zero
   `CLOCK_OFFSET_MINUTES`, is refused.
3. Storage and bank-key settings that are absent are reported as "not
   configured", not as errors.

Clock
4. `SystemClock.now()` is timezone-aware in Asia/Taipei and honours the offset.
5. A test fails if any file under `app/` other than `app/core/clock.py` reads
   the system time or uses a database time function (show it failing by adding
   such a call in a throwaway copy).

Database and migrations
6. `migrate` applies pending files once, in order; running it again changes
   nothing; an applied file whose content changed is refused.
7. Two processes running `migrate` at the same moment apply each file exactly
   once.
8. `serve` runs the migration before accepting requests, and does not start
   when a migration fails.
9. A request that succeeds commits; a request that raises rolls back
   everything it wrote.

Refusals
10. `raise Refusal(outcome, message)` yields the HTTP status of that outcome,
    the header `X-Outcome`, and the exact message: as JSON when the request
    accepts `application/json`, otherwise in an element with `role="alert"`.
11. An unknown path gives 404 and writes nothing.

Permissions and audit
12. `authorize` refuses an action that was never registered, and one whose rule
    does not explicitly allow, with FORBIDDEN and 「禁止存取」.
13. A FORBIDDEN refusal for a signed-in actor leaves exactly one new
    `ACCESS_DENIED` row naming the attempted action, in its own transaction,
    and nothing else the request wrote survives. Without an actor no row is
    written.
14. `audit.write` joins the caller's transaction: rolled back with it,
    committed with it. It refuses a type that is not in
    `docs/spec/reference/appendix-c-audit-types.md`, and a test checks the
    constants against that file.
15. `UPDATE`, `DELETE` and `TRUNCATE` on the audit table fail at the database.

Health
16. `GET /health` is 200 when the database answers and 503 when it does not,
    with no detail about configuration.

Test harness
17. With no `TEST_DATABASE_URL`, the harness starts its own throwaway
    PostgreSQL cluster (also when run as root) and removes it afterwards; with
    it set, it uses that server.
18. Each test gets its own database copied from a migrated template; data one
    test writes is not visible to the next.
19. The recorder reports no difference when nothing changed, reports an added,
    changed or deleted row in any table, and ignores only the columns in its
    explicit ignore list.
