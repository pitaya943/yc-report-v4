# 未決問題與預設答案

舊 repo 留下沒有回答的問題，加上 v2 有而 v3 沒帶過來的規則。每一題都先選了一個預設
答案，讓後續 task 不會卡住；owner 可以在任何時候改答案，「改了會影響」欄說明代價。

預設答案**還不是規格**：建置該領域的 task 會把它寫進自己的 brief，由 owner 在核准
brief 時一併決定，核准後才寫成 scenario 進 `docs/spec/`。

選擇原則沿用 v3 `definitions.md` 的三條：金額可以被人工驗算、歷史資料不被後來的
設定改寫、資料不變式永遠成立；再加一條：兩個選項都說得通時，選改起來最便宜的。

## A. v3 issue #35 的 7 個規格問題

issue 的原文在本 session 讀不到（v3 repo 沒有掛載 GitHub API）；題目取自 v3
`docs/milestones/M2.html` 第 6 至 8 節的摘要。v3 的實作都採「選項 A」，以下沿用。

| # | 問題 | 預設答案 | 理由 | 改了會影響 |
| --- | --- | --- | --- | --- |
| OQ-1 | 同時有多個 `INVALID` 原因時，回報哪一個？ | 固定順序：日期 → 數量格式 → 至少一個工項 → 共同作業者；只回報第一個 | 測試才能斷言確切的訊息；與 v3 已實作的一致 | Task 3 |
| OQ-2 | 超過 30 天的舊回報還能編輯嗎？ | 可以編輯內容；日期本來就不能改（AD-8） | 30 天限制約束的是「回報日期可以填哪一天」，不是「多久以前的回報可以改」；駁回後的修正常常超過 30 天 | Task 3 |
| OQ-3 | 對不存在的回報操作，回什麼？ | 回「找不到」（HTTP 404），不寫稽核，不屬於任何結果類別 | 規格的結果類別表沒有「找不到」；v2 在 2026-11-13 也是這個決定 | Task 2（共用的拒絕出口）、Task 3 |
| OQ-4 | 開別人回報的編輯頁被拒絕時，要寫稽核嗎？ | 要，`FORBIDDEN` 並寫 `ACCESS_DENIED` | 與 AUD-F01「每個動作都重新檢查權限」一致，讀取頁面也是動作 | Task 3 |
| OQ-5 | 直接打開帶有無效篩選條件的網址？ | 與在畫面上選到無效條件相同：清單清空、匯出停用（D-099） | 同一件事只有一種行為 | Task 3 |
| OQ-6 | 共同作業者在送出之後才變得不合格（被封存、改區）？ | 照原小組處理（AD-7：小組在送出時凍結）；之後編輯該回報時，沿用的原成員不重新檢查資格，新加入的成員才檢查 | AD-7 已同意；編輯時把原成員踢掉會讓份額因無關的人事異動改變 | Task 3 |
| OQ-7 | 自訂工項在「送出」這條路徑上算不算「有工項」？ | 自訂工項只能由管理員在審核時加上（REV-F03），員工送出時不能填；所以送出仍須至少一個目錄內的工項 | REV-F03 的規則是管理員的動作；RPT-R08 的字串是「請至少填寫一個工項數量」 | Task 3 |

## B. v2 有而 v3 沒帶過來的規則

| # | 問題 | 預設答案 | 理由 | 改了會影響 |

| OQ-8 | 同一張表單被送出兩次（連點、重新整理後重送）？ | 採用 v2 的一次性送出憑證，補上 24 小時期限；第二次送出被拒絕並顯示 v2 的字串「此回報表單已送出」，憑證過期或不存在顯示「請重新整理回報頁面後再送出」；結果類別 `CONFLICT` | v2 實際發生過重複日報；每日 3 筆的上限擋不住第 2、3 筆的重複。v2 用 400，依 AD-9 改為 409 | Task 3 |
| OQ-9 | v2 的六個登入與權限訊息（「請選擇類型」「登入嘗試過於頻繁，請稍後再試」「請求未通過驗證」「禁止存取」「請重新登入」「您已登出」）v3 附錄 B 沒有 | 先逐一核對附錄 B 是否已有等義的字串；有就用附錄 B 的，沒有才採用 v2 的字串 | 附錄 B 是 owner 同意過的字串表；v2 的字串是唯一的另一個來源，比自己發明好 | Task 2 |

| OQ-11 | 歷史清單要不要分頁、頁碼超出範圍怎麼辦？ | 依附錄 D 分頁（20、25、30 列）；頁碼超出範圍時顯示最後一頁；篩選條件留在畫面上（v2 B-063 驗收 6、7） | 附錄 D 已要求分頁，v3 沒做；容量目標是每月約 18,700 筆 | Task 3，其他清單在各自的 task |
| OQ-12 | v2 在 v3 定稿後（2026-11-17）的幾個決定：沒有變更的儲存是否仍取消確認、份額是刪除還是標記作廢、確認時不屬於該頁工項組的回報、被禁止的頁面回什麼 | 沒有變更的儲存仍回到 `PENDING`；份額刪除；不屬於該頁的回報略過；被禁止的頁面回 `FORBIDDEN`（403）並寫 `ACCESS_DENIED` | 前三項與 v3 的狀態表（「ADMIN 編輯 → PENDING，份額作廢」「略過」）不衝突；第四項與 AUD-F01 一致 | Task 3 |
