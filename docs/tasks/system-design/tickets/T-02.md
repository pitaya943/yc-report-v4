# T-02 Spike: scheduled archives on a controllable clock, and Chinese PDF / Word exports

Status: done
Serves: S-6 (b) and (d), and the "same code locally and in production" part of S-9
Depends on: nothing
Touches: `docs/tasks/system-design/spikes/` only (plus a throwaway spike branch)

## Why

The earlier build of this system (yc-daily-report-v3) deferred the scheduler
and the PDF / Word exports to its last milestones and never proved them. Before
the design is fixed we need evidence that the chosen approach works, and what
it costs.

This is a spike: the code answers a question and is thrown away. It is never
merged. What is kept is a record a person can follow to reproduce the result.

## Fixed context (already decided; do not re-open)

- Stack of the future product: Python, FastAPI, PostgreSQL, pytest. This
  machine has Python 3.13 and PostgreSQL 16 binaries (`/usr/lib/postgresql/16`);
  start a throwaway local cluster for the spike.
- The product must be deployable (likely Railway for the app, a managed
  PostgreSQL) and may run as more than one process. It must also run locally
  and in tests with no external service. Local and production must run the same
  code and differ only in configuration.
- All time comes from one injectable clock, in Asia/Taipei. Tests set the
  clock; nothing reads the system time directly.
- No real service or real personal data may be used. Network access here is
  limited to GitHub and package registries (PyPI, apt).

## Question (b): scheduled jobs

The behaviour the product must show (from the spec baseline, quoted so you do
not need the spec):

- Every day at 23:59 Asia/Taipei the day's confirmed reports are archived; on
  the last day of each month at 23:59 the month is archived (cover 2026-11-30,
  2027-02-28 and 2028-02-29).
- There is at most one automatic archive per type and date: running the job
  again after a restart does not duplicate, and two workers running the daily
  job for the same date at the same instant produce exactly one.
- The spec's scenarios are written as "when the clock reaches 2026-11-15
  23:59", so the mechanism must be drivable by the injected clock in a test.
- Expired sign-in sessions also need periodic cleanup.

Show a design that meets these and survives real deployment conditions: the
process being restarted, the trigger firing late or twice, the app being down
at 23:59 (does the archive get made when it comes back, and for which dates?),
and more than one process. Decide what triggers the job in production (an
in-process loop, a platform cron calling a command, or something else), and
keep that trigger separate from the "which jobs are due now" logic so the
logic can be tested with the clock alone. Prove the two-workers case with
truly concurrent attempts against PostgreSQL, deterministically (not a test
that passes by luck when the guard is removed: remove the guard and show it
fails every time, over repeated runs).

The archive content itself is out of scope here: a placeholder record per
archive is enough.

## Question (d): PDF and Word exports in Traditional Chinese

Required: a payroll PDF, A4 landscape, and a Word `.docx` in a bank's
salary-transfer layout; both must show Traditional Chinese correctly, also
after deployment on a Linux container with no desktop fonts.

Show, for each: the library chosen and why; a generated sample with a table of
made-up names such as 「王小明」 and amounts with thousands separators,
negative amounts distinguishable; proof that the Chinese text is really in the
file (extract the text back out and compare), and that the PDF is A4
landscape. For the PDF decide where the font comes from (bundled with the
application, a system package, or a built-in CID font), its licence, its size,
and what that means for the deployment image. For reference only, the oldest
version of this system used reportlab with the `fonts-noto-cjk` system package
and python-docx; you may confirm or replace that. The real bank sample file is
not available: reproduce a plausible transfer-slip layout (header, a row per
payee with a 14-digit account number, name and amount, a total) and state
clearly that the real layout must be matched later.
