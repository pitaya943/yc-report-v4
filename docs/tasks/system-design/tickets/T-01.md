# T-01 Spike: file storage with expiring links, and bank-number encryption

Status: done
Serves: S-6 (a) and (c), and the "same code locally and in production" part of S-9
Depends on: nothing
Touches: `docs/tasks/system-design/spikes/` only (plus a throwaway spike branch)

## Why

The earlier build of this system (yc-daily-report-v3) deferred file storage and
encryption to its last milestones and never proved them. Before the design is
fixed we need evidence that the chosen approach works, and what it costs.

This is a spike: the code answers a question and is thrown away. It is never
merged. What is kept is a record a person can follow to reproduce the result.

## Fixed context (already decided; do not re-open)

- Stack of the future product: Python, FastAPI, PostgreSQL, pytest. This
  machine has Python 3.13 and PostgreSQL 16 binaries (`/usr/lib/postgresql/16`).
- The product must be deployable (likely Railway for the app, an S3-compatible
  object store such as Supabase Storage or Cloudflare R2 for files) and must run
  locally and in tests with no external service. Local and production must run
  the same code and differ only in configuration.
- All time comes from one injectable clock. Tests set the clock; nothing reads
  the system time directly.
- No real service, real key or real personal data may be used. Network access
  here is limited to GitHub and package registries (PyPI, apt).

## Question (a): files and expiring download links

The behaviour the product must show (from the spec baseline, quoted so you do
not need the spec):

- Every open of a stored file issues a fresh link that lives exactly 3,600
  seconds: a link issued 3,599 seconds ago opens the file; one issued 3,600
  seconds ago no longer works. Links are never stored.
- Receipts are PDF, JPEG, PNG or WebP up to 10 MB: 10 MB is accepted, 10 MB + 1
  byte is refused; a GIF is refused. Decide what "type" is checked against
  (declared content type, file extension, or the file's leading bytes) and say
  why.
- A replaced file stays openable alongside the current one. Deleting an archive
  removes its stored files.
- When file storage is not configured the rest of the system keeps working: the
  record is created without a file and a download attempt warns that the file
  is unavailable.

Show a design that meets all four and is identical locally and in production:
one storage interface with at least two implementations (a local directory, and
an S3-compatible store exercised against a local stand-in such as the `moto`
server or anything else installable here), plus a "not configured" mode. Decide
who enforces link expiry (the application, with the injectable clock, or the
object store's own presigned URLs) and prove the 3,599 / 3,600 boundary with a
controlled clock. State what the choice costs in production (for example,
downloads passing through the application).

## Question (c): bank-number encryption

Behaviour required:

- By default only the last four digits are shown; the holder and administrators
  can reveal the full 14-digit number.
- The stored value never contains the plain number.
- When the encryption key is missing: viewing shows 「無法讀取」; editing is
  refused with 「銀行帳號目前無法讀取，無法修改」 and nothing is written; every
  other feature keeps working.

Show a design that meets these, using a maintained library (not hand-rolled
cryptography): authenticated encryption, the key supplied by configuration,
a way to rotate the key later without losing data (for example a key id stored
with the ciphertext), and how the last four digits are shown without the key
being needed or without it — decide which and say why. Cover: wrong key,
corrupted ciphertext, missing key.
