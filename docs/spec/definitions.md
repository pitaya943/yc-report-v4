# 本規格自行定義的規則

把規則寫成具體例子的過程中，有 13 個地方在 v2 spec 裡找不到唯一答案。每一處我選了一個答案寫進規格，對應的 scenario 標 `@assumed @AD-n`，旁邊有註解說明定義。

選擇的原則有三個：金額可以被人工驗算、歷史資料不被後來的設定改寫、資料不變式永遠成立。

**Kuei 於 2026-11-15 同意全部 13 條。** 日後要改寫時，在本檔的「狀態」欄記錄，並在改寫它的 task 的 trail 加一列。

**影響資料模型的兩條。** AD-1 需要一個「薪資批次」實體；AD-4 需要回報上多一個「工項組」欄位。這兩條若在實作後才改，要動 schema 與已存的資料。

**本規格新增的使用者可見字串。** `B 系統數值不一致，無法採用`（AD-6）、`A 系統數值不一致，無法採用`（D-075）、`回報日期送出後不可修改`（AD-8）。
